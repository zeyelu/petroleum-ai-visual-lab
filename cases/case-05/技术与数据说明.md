# 修井周期预测：模型与计算说明

版本 3.0.0 / 2026-10-29

## 目的与模型
历史修井记录常混用小时、天与班次，等待也不一定占用全部资源。只给一个总数难以解释时间消耗所在；只看平均数又会隐藏长尾等待的不确定性。

用 8 维输入，经 24→16 的共享 ReLU 网络，6 个正值工序头预测小时，5 个有序分位头直接预测总工期 Q5/Q10/Q50/Q90/Q95。独立校准集扩张预测区间；再按人数和占用规则把工序点估计换算为人时、机时。

## 数据生成与划分
根据类型、井深、复杂度等生成工序基线，加共享乘性扰动、工序噪声和等待长尾。原始标签交替以小时、天和 8 小时班次存储后统一为小时；生成式和固定种子完整留在代码中。资源开关不改变网络的工期预测，只改变占用核算。

- 输入：作业类型、井深、复杂度、班组能力、设备就绪、偏远运输条件；类型独热加 5 维训练集标准化数值。
- 标签：准备、工具入井、等待、核心处理、验证、退场六工序小时以及总小时；原始记录保留 h/d/shift 与班次长度。
- 固定种子打乱后 1200 训练 /300 验证 /250 校准 /250 测试，整条作业记录不拆散。
- 标签需完整、已结束、单位明确；网页质量检查示例展示未知班长、缺失和未结束如何被拒绝。

## 训练
损失 = 3×六工序归一化 MSE + 五个分位的平均 pinball loss，小时除以 80 学习后还原。分位头的正增量累加避免交叉。校准修正 max(下界−真值, 真值−上界,0)，仅扩张；报告支持过滤后的覆盖与可用比例。

实际预训练 65 轮，验证最优第 43 轮，参数 803 个。数值可在“训练与检验”中查看并通过导出快照保存。

## 交互与可视化
工序条形图回答时间花在哪里，甘特图解释串行累计，区间图呈现不确定性，散点图检验偏差。点估计、覆盖、可用性和资源假设分别呈现，避免用一个精确数字掩盖条件。

### 1. 清洗记录
输入：混合时长单位。输出：完整小时标签。

小时、天和明确长度的班次统一，拒绝缺失、未完工及工序不全的标签。

注意：不知道班次长度不能默认按 8 小时换算。

页面位置：单位质量检查表

### 2. 准备特征
输入：作业描述。输出：8 维编码与分组。

作业类型独热，其他五维使用训练统计标准化；四个集合各自承担不同作用。

注意：不能用测试记录选择模型或校准区间。

页面位置：数据档案与集合筛选

### 3. 联合学习
输入：输入与工期标签。输出：六工序 + 五分位。

共享表示兼顾工序点预测和总工期分位，softplus 保证正值与分位有序。

注意：分位数不是均值，点预测总和与中位数头可以不同。

页面位置：工序条形图与训练曲线

### 4. 校准区间
输入：250 条校准记录。输出：80% /90% 区间。

取有限样本分位修正，扩张上下界；附近样本不足时暂停输出校准区间。

注意：同分布边际覆盖不保证每个单井或筛选子群都达到目标。

页面位置：原始与校准区间、支持提示

### 5. 计算资源
输入：工序小时与占用假设。输出：日历 / 人时 / 机时。

按串行工序绘制排程，人数乘占用小时得到人时，准备不计机具占用。

注意：不含并行排程、班次冲突和真实资源优化。

页面位置：甘特图、等待占用与人数开关

### 6. 比较复核
输入：测试记录与参考。输出：误差 / 覆盖 / 可用性。

保留近邻参照，独立测试绘制实际—预测散点与区间覆盖，导出模型。

注意：网络更复杂不保证 MAE 更小，条件对照不是因果干预结论。

页面位置：测试散点、区间与导出

## 与旧版的区别
新模型使用真实 TensorFlow.js 张量和反向传播，在浏览器 CPU 上可重新训练。原算法仍用于规则或参考对照，不把旧分数改名为神经网络。训练、验证、测试和校准用途各自明确。

## 参考与边界
这是结构化回归，不包装成时序 LSTM。六工序点预测可以相加，六工序分位数不能相加充当总分位。资源是固定配置换算，不是最优排班或人员数量推荐。

- [TensorFlow.js · 浏览器机器学习](https://www.tensorflow.org/js)
- [Romano 等 · Conformalized Quantile Regression](https://arxiv.org/abs/1905.03222)

参考论文提供通用方法，不表示复现其完整架构、实验或石油工程效果；本案例是小规模教学变体。
